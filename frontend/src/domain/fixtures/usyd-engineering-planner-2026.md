# USYD Engineering 2026 acceptance evidence

Captured through read-only local degree, component, study-plan and candidate-source APIs on 5 October 2026. No database writes, imports, collector commands, schema changes or migrations were performed.

`usyd-engineering-planner-2026.json` retains the degree requirements, all 12 complete stream structures, 24 representative CUSP layouts, a layout/192 CP verification record for each of the 196 actual plan IDs, exact-code candidate-source membership results for the 182 unique formal specialisation subjects, and the first 20 canonical subjects from each degree candidate source. It complements the existing `usyd-engineering-breadth-2026.json` relationship/component/plan-metadata fixture. Both are test evidence only; production reads the APIs.

Named variants reuse their corresponding captured layout in tests because the API audit found identical schedule content after normalising alternative-row order. This does not assert that their formal academic requirements are identical. Production retains the actual selected CUSP variant and API schedule.

## Deliberate limits

Eight of the 49 referenced specialisation components have fully structured evaluable CP groups: the four Breadths, Software Data Science, Civil Humanitarian, and the two Mechanical Industrial/Product Design identities. The other 41 retain UNKNOWN logic and show observed membership CP with manual verification. CP totals are not guessed from titles, prose or list length.

CIVL5330 is listed in the official Humanitarian Breadth table but absent from both persisted Engineering UG and Table S candidate sources. Its Free Elective eligibility cannot be verified from those APIs. It remains visible in formal requirements, is excluded from the focused slot intersection, and is named in the dialog's limitation notice. No production membership was fabricated and no database repair was attempted.

Source counts remain Engineering UG 271, Table S 1472 and Table D 17. Production verifies focused membership with at most four concurrent exact-code requests, caches canonical results within the session, and preserves the ordinary paged eligible pools. Test fixtures are never imported by production code.

## Acceptance and scope audit

The durable domain tests independently exercise every stream/focus/commencement/compatible variant, compare 30 representative handbook membership tables, and check same-name parent collisions. Evaluable models cover empty, partial, exact, extra, moved, holding-area, removed, reset and reloaded selections, including ALL, ANY and ONE_OF semantics. UNKNOWN, missing records/CP, overlapping requirements and inconsistent totals remain manual.

The browser matrix visits every one of the 196 variants. Additional scenarios cover formal-versus-preview independence, Base and another manual focus preserving formal selections, stream changes, focused membership failure/retry, ordinary pool fallback, search, allocation ownership, holding-area persistence, transient delete feedback and UNKNOWN completion refusal. Existing UTS and other-degree regression scenarios remain unchanged.

Live Edge review used real local API responses at 1440×1050 and 900×1000, with a temporary request forwarder to bypass a stalled Vite proxy. It confirmed the four eligible Humanitarian Breadth rows and CIVL5330 notice, selected CP increasing from 138 to 144 while formal progress increased from 0/24 to 6/24, reversible Base preview, stream isolation, Mechanical Industrial/Product Design, readable selectors/cards and a chooser fitting the narrow viewport without horizontal overflow or page errors. The review found and corrected an inconsistent warning count: the USYD summary now distinguishes deduplicated warnings from informational handbook verification notes.

Production changes are confined to 15 USYD files and one optional presentation prop in `SubjectChoiceDialog.tsx`. Only the USYD personal planner supplies that prop; with it absent, pool resolution, allocation, search, paging, defaults and rendering retain their existing paths. Earlier shared changes to `RequirementAccordion.tsx` and `componentDetailState.ts` were restored, and USYD optional-component behavior now lives in its own wrapper. No UTS production code, non-USYD fixtures, shared domain rules, backend production services, database/schema/migrations, collectors or Vite configuration were changed.

Final validation on 5 October 2026: backend read-only tests 24/24; frontend domain tests 146/146; full Playwright suite 70/70 in development and again against the final production build (2.2 minutes). Frontend and backend builds/typechecks and the explicit TypeScript check for the new browser suites passed. The temporary browser forwarder, local captures/scripts/screenshots and Playwright artifacts were removed after review; only durable code, regression tests and these provenance fixtures/docs remain. No changes were staged or committed.
